# Forklight Demo Script

Target: 2:20–2:40.

## 0:00–0:15 — Problem

Visual: MAIN warehouse, boxes backing up.

Voice:

> Agents are getting better at changing live software. But today, they often have to experiment on the state we actually care about.

## 0:15–0:30 — Thesis

Visual: MAIN splits into three branch cards / futures.

Voice:

> Forklight gives an agent isolated futures. It can try alternatives, verify them, and only a human-approved future can become real.

On-screen:

**Try the future before you merge it.**

## 0:30–1:30 — Real site tools

Use the real ChatGPT in-app browser session.

Agent:
- inspect world;
- inspect constraints;
- create A/B/C;
- apply locked mutations;
- simulate;
- validate.

UI must visibly switch / update as tool calls occur.

## 1:30–1:50 — Compare

Show:

```text
A — FAIL: distance
B — VERIFIED
C — FAIL: protected equipment
```

Voice:

> The simulator checks hard constraints deterministically. The agent can explore, but it cannot declare its own future safe.

## 1:50–2:10 — Human capability handoff

Human clicks:

**Approve Future B**

Show:

**CAPABILITY UNLOCKED**

Agent discovers:

`merge_verified_branch`

Agent invokes it.

MAIN changes.

## 2:10–2:30 — Meaning

Voice:

> The agent explored. The simulator verified. The human decided. And WebMCP changed what the agent was actually allowed to do.

## End card

**Forklight**  
**Try the future before you merge it.**

## Recording rules

- real tool calls only;
- real validation only;
- no fake timeline;
- no pre-rendered "agent working" simulation;
- successful session recording may be edited for pacing;
- record a backup successful session before the final take.
